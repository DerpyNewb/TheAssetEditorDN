VFX Editor

Warhammer III's particle effects live in vfx/*.xml files. The VFX editor opens one as a tree, gives you a form for every value in it, and plays the effect in a preview that catches up with your edits as you make them. You don't hand-edit XML, and you don't launch the game to find out whether a number did anything. You'll still want the game before you ship, and what the preview won't tell you says why.

The VFX editor is in the DN fork's releases from v0.78-dn-v1 on, on the fork's releases page. This page was written against v0.78-dn-v1.2.

The first half of this page is a guide. Then comes a tutorial that makes a dark red version of CA's war machine steam and puts it on an animation, a section on building your own emitters, and a table of things that go wrong.

How an effect file is put together

You need five ideas to get around. None of them is hard.

The name

An effect is a file at vfx/<name>.xml, and <name> on its own (no folder, no .xml) is how the rest of the game asks for it: an animation's EFFECT tag puts it in Vfx Name, a DB table puts it in a column. Keep it lowercase. All 8,308 of CA's effect files are, and WH3 has had trouble with uppercase pack paths since patch 6.1.

Libraries and reference files

CA splits effects in two. A library (construction_type="1" on the <vfx> line) defines emitters, the things that actually spawn particles. A reference file (construction_type="2") usually defines none. It points at one or more libraries and, for each of their emitters, says whether it's on, how much to tint it, how fast it spawns and how long it lives. 1,401 of CA's 8,308 files are libraries. Most effects you'd hang on a unit are reference files, and that's handy: the reference is where most of your changes go, and the library stays CA's.

An emitter is three records

Each emitter has three parts that share one id. The emitter itself holds spawning: rate, speed, lifetime, size, forces. Its behaviour chain says how each particle is drawn, built from modifiers such as ps_texture (the texture), vs_colour (colour over life) and vs_vertex_alpha (fade over life). Its render stack says which render layer it goes in: ordinary particles, heat haze, decals on the ground, or light. The editor shows all three under the emitter, so you rarely think about it, but it's why Duplicate and Rename change three places at once.

Quality tiers

A value can differ per graphics setting. Tier 0 is what Ultra effects quality reads and tiers 1 and 2 cover the settings below it; the editor calls them Ultra, High and Medium. Emitter and render stack values fall back to Ultra's when a tier doesn't set its own. Behaviour chains don't fall back: a chain with no block for a tier draws nothing on that setting, and nothing anywhere tells you. CA gives all 14,137 of its chains all three tiers, so this only bites hand-made effects. The editor warns you (see the quality trap).

Curves

Most numbers are curves rather than single values. They run over the life of the particle or the emitter, from 0 (birth) to 1 (death). A curve has channels, usually in pairs like x_min and x_max, and a mapping that says what to do with them: take a random point between min and max, or take the min. A steam puff that lives "2.5 to 4 seconds" is a ParticleLifeTime curve with x_min at 2.5, x_max at 4.0 and a mapping that picks between them.

Opening an effect

Load the game's packs first (CA's effect files are in vfx_desc.pack, their textures in vfx.pack) and have an editable pack: File > Create a new packfile makes one, or right-click a pack and pick Set as Editable Pack. PackFile Handling covers the rest.

Then either:

  • Tools > VFX Editor opens an empty tab. Open picks an .xml from the loaded packs, and New starts an empty effect.
  • Double-click a file under vfx/ in the pack explorer. The text editor claims .xml files too, so the AssetEditor asks which one you want. Pick the VFX editor.

Only files in a vfx folder open here. One that isn't an effect gets a message telling you to reopen it in the text editor.

The first editor you open reads CA's effect files in the background to learn its vocabulary: which words belong in which dropdown, and which properties CA uses where. The status line says "Reading vanilla effects", then how many it read. Until it finishes the dropdowns are plain text boxes, and anything you type meanwhile is kept.

Finding your way round

Three panes: the tree on the left, the values in the middle, the preview on the right. The toolbar is along the top. The status line along the bottom says what just happened, including why an edit was refused, so if a click seems to do nothing, look there first.

The tree

A chain labelled "Behaviour chain (draws nothing at this tier)" is the quality trap.

The values

Pick something in the tree and its values appear in the middle, one row each: a checkbox for true and false, a dropdown where CA only ever writes a handful of words, and a text box for the rest. Type a value, then press Tab or click elsewhere to commit it. A number that doesn't parse gets a red border, and the file keeps its old value.

A row holding a file path (a texture, a material) gets Browse, which picks from the loaded packs, and Open, which opens the file in the app; a material opens in the text editor. Texture rows show a thumbnail too.

A curve row opens into a small curve editor under it:

  • The Channel dropdown picks a channel. Its keys fill the table: time, value, the in and out interpolation, four tangent numbers and a flag.
  • Add key copies the picked key to a point halfway to the next one. Delete key removes it, but a channel always keeps one.
  • Copy channel puts a copy of the picked channel at the end of the list. Remove channel deletes one, unless the mapping still reads it.
  • The Mapping box holds the text CA writes, output,random;min,max for each output, joined with |. x,1;0,1 means x is a random point between channels 0 and 1. x,0;0,1 means x is channel 0.
  • The graph draws every channel from 0 to 1, the picked one thicker, with the value range printed under it.

Above the rows is a strip of buttons that changes with what you picked in the tree:

Quality and linked edits

The Quality dropdown on the toolbar picks the tier you're looking at and editing. Edits are linked by default: every tier that held the old value takes the new one, so tiers that matched stay matched. Tick "This tier only" to change just the tier on screen. On High or Medium, each row is marked "this tier" or "from Ultra" so you can see where its value comes from. If a tier's modifiers don't line up with the ones on screen, a linked edit leaves that tier alone, and the status line names it.

The preview

The preview plays the effect at the tier on screen, unsaved edits included. It catches up 300 milliseconds after your last change, so typing a number re-simulates once rather than on every key.

ControlWhat it does
Play, Loop at, Speedplayback. One loop lasts the Loop at seconds, and the slider scrubs through it

Projectile, Velocity, Axisflies the effect along one of its own axes at Velocity metres a second, crossing the centre halfway through each loop. This is the one for trails. For scale, CA's arrows fly at 54, muskets at 100, and the median projectile at 67

Under the viewport, a list shows up when the preview couldn't find something (a texture or a library that isn't in the loaded packs) or left something out. It takes no room when it's empty.

Saving

Save (Ctrl+S) writes the file to its own path in your editable pack. Save As asks for a new path, and a new effect asks the first time you save it.

If you opened one of CA's effects, Save writes CA's file into your pack under CA's name. That overrides it for every unit, spell and building that uses it, not just the one you had in mind. Sometimes that's the point. Usually it isn't. When you start from a CA effect, Save As under your own name before you change anything. The tutorial does exactly this.

Edits only touch the bytes they change, so a file you open and save without editing comes out byte for byte the same, in the same text encoding: CA's are UTF-16, and a hand-written UTF-8 file stays UTF-8. The game reads both. Undo and Redo (Ctrl+Z, Ctrl+Y) go back 100 edits.

What the preview won't tell you

The preview follows CA's formats and shaders as closely as they could be read, but it isn't the game's renderer, and it hasn't been checked frame by frame against CA's own effect editor yet. Use it for placement, timing, size, colour, and whether your edit did anything at all. Then look at the effect in SuperView on its animation, and in a battle, before you ship. The known gaps:

  • It plays at the origin, with no bone and no animation. Save, and SuperView picks the change up on the unit.
  • Wind and SpreadArc aren't simulated.
  • Decals lie flat on the ground at height 0, never on models.
  • Soft, see-through fire edges come out a bit darker than in game, because the game blends in linear light and the preview doesn't.
  • The app's default sun is about three times brighter than an overcast battle map's, so smoke can look lighter than it will in game. Lighting... turns it down.

Tutorial: dark red steam for a war machine

CA's war machines vent white steam. You'll make a dark red version, check it in the preview, and put it on an animation. On the way you'll use the reference-file workflow, which is how CA tints and trims its own effects.

You need the DN build, the game's packs loaded, and an editable pack. Pick a short lowercase prefix for your files so they don't collide with anyone else's. This tutorial uses mymod_.

Step 1: open CA's steam

Tools > VFX Editor, then Open, and find vfx/wh_main_machine_steam_exhaust.xml. The browser's filter box saves scrolling past the other 8,307. You can also double-click it in the pack explorer, under vfx_desc.pack.

The tree shows Effect, an empty Emitters (this file defines nothing itself), and under References, wh_main_lib_machine_hellcannon_exhaust (main) with six rows:

  • exhaust_embers (off)
  • exhaust_smoke (off)
  • exhaust_souls (off)
  • rising_steam
  • ice_mist (off)
  • ice_decal (off)

So CA's steam exhaust is one emitter, rising_steam, borrowed from the Hellcannon's exhaust library with the other five switched off. Press Play to watch it.

Click the reference itself. Among its rows, scale_min 0.95 and scale_max 1.05 give it a little random variation in size, and infinite_life true leaves each emitter to its own setting; rising_steam's is to run until the animation tag that plays it ends. Now click rising_steam: its tint runs from 0.84 on red, green and blue (tint_min) to 1.00 (tint_max), light grey to white, and both alphas are 0.10.

Step 2: make it yours

Before touching anything, Save As, and type the path vfx/mymod_dark_steam.xml. The tab now edits your copy, and the status line says "Saved mymod_dark_steam". CA's file is untouched, and the game now has an effect called mymod_dark_steam.

Step 3: tint it

With rising_steam picked, change these six rows:

RowCA's valueYours
tint_min_r0.840.46
tint_min_g0.840.05
tint_min_b0.840.04
tint_max_r1.000.55
tint_max_g1.000.06
tint_max_b1.000.05

Leave both alphas alone. Alpha is how see-through the steam is, which is a separate thing from its colour.

A tint multiplies the colour the library already gives each particle. For this steam that's white to light grey, so the tint is close to the colour you'll see. The min is 84% of the max, as in CA's version, so the puffs still come out in slightly different shades. The preview catches up a moment after each value you commit.

Values above 1 brighten past the texture's own colour, and nothing stops you going high. For a sense of scale: 95% of CA's switched-on emitters peak at a tint of 1.5 or less, and the brightest projectile trail CA ships peaks at 20.

Step 4: more steam (optional)

To vent harder, raise spawn_rate_scale_factor_min and spawn_rate_scale_factor_max on the same row. 1.5 gives half as much steam again. That's an override in your reference file, so the library stays CA's and stays shared.

You can switch emitters on as well. Tick enable on exhaust_embers and see what the Hellcannon's embers add, then untick it if you don't want them. All on and All off, on the reference, flip every row at once.

Step 5: check it against something real

Steam floating in empty space tells you nothing about size. Click Model... and pick the war machine's .rigid_model_v2 (any model works as a ruler). It stands where the effect spawns. If the steam looks pale, open Lighting... and bring the light intensity down, since the preview's default sun is brighter than most battle maps.

This file has no behaviour chains of its own, so the Quality dropdown changes nothing here; the library already covers all three tiers. Press Ctrl+S.

Step 6: put it on an animation

An effect plays when an animation's meta file has an EFFECT tag naming it. There are two ways to get one.

If you're recolouring steam a unit already has, find the .anm.meta that plays the white steam. On a war machine the always-on steam usually sits in the persistent meta, the one that runs for as long as the unit is alive. Open it, find the EFFECT tag whose Vfx Name is wh_main_machine_steam_exhaust, and change it to mymod_dark_steam. The bone, offset and timing stay as CA set them.

If you're adding steam somewhere new, click New in the meta editor, filter the Create MetaData entry window for EFFECT, pick EFFECT_12 (its "Vanilla WH3 uses" column shows it's the version CA uses on most EFFECT tags), and click Add. Then fill in:

FieldWhat to put
Vfx Namemymod_dark_steam, with no folder and no .xml
Node Indexthe bone it sits on. -1 is the model's origin. Copying the number off an existing tag on the bone you want is the quick way
Position, Orientationthe offset from that bone
Trackingon, so it follows the bone. Off, it stays where the bone was when it started
Start Time, End Timewhen it plays. 0 and 0 plays for the whole animation
Id0, so it plays on every unit that uses this meta. Any other number plays only on battle entities whose vfx_filter_id matches

Save the meta and open the unit in SuperView with Show VFX ticked. The effect draws on its bone with its name beside it. "(not found)" after the name means no loaded pack has vfx/mymod_dark_steam.xml, so check the spelling. SuperView reloads when a vfx file is saved, so you can keep the VFX editor open in another tab and keep tweaking.

Several units often share one of CA's metas. Save CA's meta into your pack and you've changed the steam on all of them. To change one unit only, give it its own copy of the meta through its animation fragment. That's an animpack job, and outside this page.

Step 7: ship it

Your pack needs vfx/mymod_dark_steam.xml at that path, and if you saved into your editable pack, it's already there. An ordinary mod pack is fine. The meta editor's tooltip on Vfx Name says effects need a movie-type pack, but effects in mod-type packs load and draw in WH3.

An effect that only an EFFECT tag plays needs no database row. If a DB table names it instead, a projectile's trail or explosion for example, also add its name to particle_effects_tables, which has a single column. CA's lists 2,084 effects: the Magma Cannon's explosion, which projectiles_explosions_tables names, is in it, and the steam exhaust, which only animation tags play, isn't.

Then look at it in a battle. Dark tints on thin smoke can come out nearly black. If yours does, raise the red and look again.

Going further: your own emitters

When a reference can't do what you want (a different texture, a new size curve, a particle no library has), you're editing a library. Same rule as before: don't save over CA's. Open the library, Save As under your own name, say vfx/mymod_lib_exhaust.xml, and make your changes there. Then pick the reference in your own effect and set its vfx_ref row to mymod_lib_exhaust. Your copy keeps CA's emitter ids, so the reference's rows still match.

An example: bigger puffs

In your library copy, open Emitters > rising_steam and find ParticleScale, the puff's size over its life. It has six channels, a min and a max for each of x, y and z, and the mapping x,1;0,1|y,1;2,3|z,0;4,5: width is a random point between channels 0 and 1, height between 2 and 3, and z is channel 4. Pick x_max and you'll see four keys. The puff starts at 0.5, swells to 5.0 about three quarters of the way through its life, and ends at 2.5. Raise that 5.0 and the biggest puffs get bigger. Do the same on y_max, or the puffs stretch sideways instead of growing.

Starting from nothing

Pick Emitters, type an id, choose a type, and click New emitter. For continuous_mesh you get 32 properties and the six modifiers most of CA's mesh emitters carry (vs_colour, vs_vertex_alpha, ps_texture, ps_lighting, ps_soft_edge, vs_translation), all filled with CA's most common values and identical at all three tiers. It's a starting point, not an effect: Browse a texture onto diffuse under ps_texture, shape the colour and alpha curves, and go from there.

Duplicating is often quicker. Pick an emitter close to what you want, type a new id, click Duplicate emitter, and change the copy. Remove emitter takes the emitter, its chain and its render stack together. Rename changes all three too, but it can't fix references to the old id from other files, and the status line reminds you.

The quality trap

If a behaviour chain says "No modifiers at this tier, so it draws nothing", that emitter is invisible on that graphics setting in game. Click "Copy Ultra's block here". That's what CA does: 13,884 of its 14,137 chains are identical across the three tiers. Check all three before you ship anything with emitters of its own.

Campaign textures

If your effect plays on the campaign map and uses a texture you made, encode it as BC7_UNORM_SRGB with mips, for example texconv -f BC7_UNORM_SRGB -srgb -m 0 smoke.png. All 93 diffuse textures CA's campaign libraries use are in that format, and a single DXT5 texture behind one modded campaign effect has been seen turning every CA smoke, ember and magic particle on the map into a flat translucent square, from the moment the campaign loads. Pillow can't write BC7, so it has to be texconv (or something else that can).

Effects that never stop

infinite_life true on a reference leaves each emitter to its own setting. Switch on a looping emitter, a firebox flame say, inside an effect an attack plays, and every swing leaves a fire that never goes out. Leave looping emitters off in one-shot effects, or set infinite_life to false on the reference, which ends every looping emitter under it. 154 of CA's impact and explosion references do exactly that.
