Your First Kitbash: Swap a Helmet

This page walks through one complete change, from opening a unit's model to seeing it in a battle. The example gives a unit a helmet taken from another model, but the same steps work for a weapon, a shoulder plate or any other part.

Before you start: AssetEditor needs the game's packs loaded and an editable pack to save into. PackFile Handling explains both. Everything you save goes into the editable pack, and nothing in the game's own packs is changed.

1. Find the unit's model

A unit's look is set by a variant mesh definition, a file under variantmeshes/variantmeshdefinitions/. The database picks it for the unit in two steps: the unit's row in unit_variants_tables names a variant, and that variant's row in variants_tables gives the file name in variant_filename, without the extension. You can read both tables in RPFM or in the WH3 Mod Manager's DB viewer.

Open the definition from the pack explorer and pick the grid editor when AssetEditor asks. Each row is a slot, such as the body, the head or the helmet, and the Path column shows the model each slot uses. Note the helmet slot's path. It ends in .wsmodel or .rigid_model_v2.

2. Open the helmet in Kitbash

Open the helmet's model from the pack explorer. Kitbash opens it as the Editable Model, which is the part that gets saved.

To see the helmet on the unit while you work, click Import Reference model on the icon bar and pick the unit's variant mesh definition. Reference models are drawn but never saved, so the body is there for fitting only.

3. Bring in the new helmet

  1. Click Import Reference model again and pick the model that has the helmet you want.
  2. In the scene explorer, right-click that helmet's mesh and choose Make Editable. It moves out of the reference models and into the Editable Model.
  3. Select the old helmet's mesh and delete it. If you'd rather keep it for comparison, hide it instead and tick Only save visible nodes when you save.

4. Fit it

Use the move, rotate and scale gizmos on the icon bar to put the helmet on the head. Snap to bone or vertex moves the selection onto a bone, such as head, which is a quick way to get it close before fine-tuning. If the helmet's shape doesn't match the head, the Mesh Fitter can reshape it.

5. Make it follow the animation

A mesh only moves with the unit if its vertices are weighted to the unit's bones. Which tool you need depends on where the helmet came from:

  • A model on the same skeleton: its weights already name the right bones, so there's usually nothing to do.
  • A model on another skeleton: open the re-rigging tool and map each bone the helmet uses to a bone of this unit's skeleton. OK stays disabled until every bone has a target.
  • Any rigid part: open the Pin Tool, choose Bone mode and pick head, from the list or by turning on bone picking on the left sidebar and clicking the head. Every vertex then follows the head bone fully, which is right for a helmet.

To check the result, turn on Show the selected bone's weights in the Skeleton panel and pick the bone. Blue means the bone doesn't move that vertex at all and red means it moves it fully. Then play an animation and watch the helmet stay on the head.

6. Check and save

Click Check model. It lists vertices with no bone weights, weights that don't add up to 1, textures that aren't in any loaded pack, and base colours with no sRGB flag, with a fix button beside the problems it can fix. The Kitbash Tools page explains each one.

Then save. In the save dialog:

  • Set Path to a new file of your own, under your own folder. Saving over the original's path changes every unit that uses that helmet, which is rarely what you want.
  • Set WS model Format to Warhammer3, so a .wsmodel is written next to the model. The .wsmodel is what gives the model WH3's materials, such as faction colours.
  • Leave Mesh Format and Lod Strategy at their defaults unless you have a reason to change them.

7. Point the unit at the new helmet

  1. In the pack explorer, right-click the unit's variant mesh definition, choose Copy to editable pack, then Rename the copy so it doesn't replace the original.
  2. Open the copy in the grid editor and change the helmet slot's Path to your new .wsmodel. Save it with Ctrl+S.
  3. In RPFM, add a row to variants_tables for your copy. Copy the unit's original row and change variant_name to a new key and variant_filename to your copy's file name, without the extension.
  4. Still in RPFM, copy the unit's row from unit_variants_tables into your pack and change its variant to your new key.
The shortcut: if you do want every unit that wears this helmet to change, save your model over the original's path in your pack and skip step 7. Your file then replaces CA's for every unit that uses it.

8. Test in game

Save the pack, enable it in the launcher or the WH3 Mod Manager, and start a custom battle with the unit. Zoom in on a few soldiers and watch them move. If something looks wrong:

What you seeWhere to look
The helmet is missing or invisible.The variant mesh definition's path, or textures the Check model step reported as missing.
The helmet stretches or tears when the unit moves.Its weights: check them with the weight view and redo step 5.
The helmet floats in place while the head moves.It has no weights at all. Use the Pin Tool's Bone mode.
The helmet is too bright or has no faction colours.The .wsmodel: save again with WS model Format set to Warhammer3, and check the base colour texture's sRGB warning.
